Arms and rosters

An arm is one evaluated pipeline: a selection sweep (the scorer and the native width axis it is swept on) composed with a local optimizer and a width parameterization. A paper builds its arms in one Roster value and hands it to every reader of a tuned operating point; the readers refuse an operating point that the cross-validation window clipped. See the Overview for how the pieces fit together.

Composed and solo arms

LocalOptimizationDoneRight.ComposedSpec — Type
ComposedSpec(base, sel, selection::WidthAxis, kind::WidthAxis, ctor; source = TunedWidth())

One composed score+LO pipeline. sel is the key of its selection sweep (the selections idxs_of[sel] a refit seeds from); selection is that sweep's native axis — RansacScoringDoneRight's native_axis of the selection scoring (OutlierHalfwidth() for the Student-t marginal, LossWidth() for a threshold score); kind is the arm's width parameterization; ctor(value) builds the LO strategy at a width value (a scale-multiple arm bakes it in; the other kinds deliver it through their port, see width_delivery); source is where the width value comes from (WidthSource): a SelectionWidth arm requires kind == selection, and the tuning skips it.

LocalOptimizationDoneRight.SoloSpec — Type
SoloSpec(base, role, axis::WidthAxis, ctor)

One role (:selection | :refinement) validated in isolation at one width value on axis (see the block comment above); ctor(value) returns a pool scorer (selection) or an LO strategy (refinement).

source
LocalOptimizationDoneRight.Roster — Type
Roster(composed, solo, basin)

A paper's arm roster, the argument of every reader that rebuilds arms from a tuned sidecar (deployed_budget_settings, deployed_basin_settings, audit_operating_points). Each field is the paper's builder:

  • composed(problem::Symbol) -> Vector{ComposedSpec} — the composed score+LO roster (scale-multiple / outlier-half-width / natively delivered loss-width arms) of the composed miscal and budget evaluations;
  • solo(problem::Symbol; role::Symbol) -> Vector{SoloSpec} — the solo roster;
  • basin(problem::Symbol) -> Vector{ComposedSpec} — the basin roster (loss-width and outlier-half-width arms only; a scale multiple has no meaning on the basin axis).

LocalOptimizationDoneRight.operating_width — Function
operating_width(arm::ComposedSpec, selection, tuned) -> Float64

THE refit width of arm at the tuned selection width selection. By its WidthSource: a TunedWidth arm's tuned value tuned; a SelectionWidth arm's selection itself — tuned is nothing (the tuning stage, which has none) or a recorded width, which must equal selection exactly (a sidecar read back).

LocalOptimizationDoneRight.width_delivery — Function
width_delivery(P::WidthAxis, lo, value, n) -> NamedTuple

How a width value reaches the refit of lo over n columns, as LoRefitSpec keyword ports. A scale multiple is baked into the LO object; an outlier half-width rides the natives port; a loss width the port of its LO type (loss_width_port) — the s2s (s2_override) port at the unit-multiple ctor, the solo delivery bitwise (the seed sweep runs at the selection native), or the natives port.

Evaluation refits

LocalOptimizationDoneRight.solo_refit_imc! — Function
solo_refit_imc!(ctx, spec::SoloSpec, seed_E, width, selection_halfwidth; on_fail = NaN)
    -> (imc°, lo_ns)

THE width-delivery dispatch of a :refinement solo evaluation. It is one mechanical map from spec.axis (and, for a loss width, the LO type's loss_width_port) to the refit call, shared by the basin tuning's refits and the ladder's solo mode so tuning and test deliver the width identically:

  • LossWidth(), OverridePort — unit-multiple ctor + s2 = width² through refit_imc! (the locally_optimize s2override port); the seed sweep runs at `selectionhalfwidth` (scoring only, never a width).
  • LossWidth(), NativePort, and OutlierHalfwidth() — the LO at its own native nat′ = width.

LocalOptimizationDoneRight.miscal_evaluation_refit — Function
miscal_evaluation_refit(arm, idxs_of, tuned, zetas, grids; d_g, plugin_scale = nothing) -> LoRefitSpec

The miscalibration evaluation refit of one arm, one column per ζ in zetas. Column j seeds at the selection column nearest ζj·selection* and refits at the exactly-scaled refinement native (ζj·width* for the native parameterizations — both formed from the corrupted plug-in — while a scale multiple is partition-anchored and NOT corrupted). tuned is the tuned point as NATIVE VALUES, (; selection, width), its width read through operating_width (a SelectionWidth arm: width is nothing or the selection, and column j refits at ζ_j·selection*, the selection's own corrupted native); grids supplies the arm's selection grid, which the seed columns are found in.

plugin_scale (the partition-anchoring ABLATION, scale-multiple arms only): the same operating point and seeds, the scale multiple's loss width delivered at the FIXED external plug-in scale ζj·`pluginscaleinstead of the seed partition's ŝ —withscale(lo, FixedScale((ζj·pluginscale)²))through the LoRefitSpecfixedscale_s2s` port. A native parameterization's width already is the corrupted plug-in; it is refused.

Gate-enforced readers of a tuned operating point

LocalOptimizationDoneRight.deployed_budget_settings — Function
deployed_budget_settings(roster::Roster, path; problem = nothing)
    -> Vector{label => (lo, sel, ref, kind)}

Per-arm tuned operating points of a composed tuning sidecar, rebuilt through the roster. The sidecar is read through VisualGeometryEval load_tuning_artifact, which refuses another format; each arm is rebuilt through roster.composed(problem): the LO instance (the tuned scale multiple baked in for scale-multiple arms), the SELECTION native and the REFINEMENT native (scale-multiple arms refit at the selection native — partition-anchored; native parameterizations at their tuned value) and the arm's width parameterization kind — the roster's, the one source of an arm's kind (a sidecar's own kinds list is not read). problem defaults to the sidecar's own "problem".

INTERIOR-ARGMIN INVARIANT: a HARD ERROR on any arm whose persisted boundary_hits is non-empty — expand the window on the flagged side and re-run the tuning (a SelectionWidth arm has no width of its own to clip: its list carries the selection's axis alone, and its recorded width must be its selection's, operating_width). A basin sidecar is refused (deployed_basin_settings reads it).

source
LocalOptimizationDoneRight.deployed_arm_settings — Function
deployed_arm_settings(roster::Roster, path; problem = nothing) -> Vector{label => (lo, fixed_native)}

Each pipeline's DEPLOYED configuration: the LO strategy at its tuned width and its fixed native. It is the (lo, ref) projection of deployed_budget_settings, under the same interior-argmin gate.

source
LocalOptimizationDoneRight.deployed_basin_settings — Function
deployed_basin_settings(roster::Roster, path)
    -> Vector{base => (spec::SoloSpec, width::Float64)}

Each basin arm's tuned width from a basin tuning sidecar (mode = "basin"). The arms are rebuilt through roster.basin(problem) and repackaged as a refinement SoloSpec whose axis is the arm's parameterization, so tuning and test deliver the width identically via solo_refit_imc!. Refuses a non-basin sidecar. Same interior-argmin gate as the composed readers.

source
LocalOptimizationDoneRight.audit_operating_points — Function
audit_operating_points(roster::Roster, path; problem = nothing) -> true

Audit the tuning sidecar at path through its gate-enforced reader. A basin sidecar goes through deployed_basin_settings, a composed one through deployed_budget_settings; it throws on any clipped arm (a boundary argmin never reaches a consumer) and on any other artifact format, and returns true. MANDATORY before a figure or table consumes the sidecar.
