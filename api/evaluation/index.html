Evaluation engines

Post-LO error matrices

A selection sweep (RansacScoringDoneRight's grid_evaluate) records, per pair and grid column, the pool model the scorer selected. apply_lo_refits turns a vector of LoRefitSpecs into post-LO error matrices over the same grid; stream_selections feeds it scene by scene.

LocalOptimizationDoneRight.LoRefitSpec — Type
LoRefitSpec(label, lo, axis, grid, idxs; bundle=false)

One post-LO refit of a selection sweep: refine the selected model idxs[p, t] with strategy lo at native parameter consumed_native(lo, axis, grid[t]). axis is the SELECTOR grid's native axis (a NativeAxis: OutlierHalfwidth() | LossWidth()) — cross-axis conversion happens per column inside the refit layer, so callers never pre-convert grids. lo = NoLocalOptimization() records the selection imc (no refit).

Column t refits the model selected at column seedcols[t] of idxs at the EXPLICIT native value natives[t] when those fields are set (no consumed_native conversion — the value is already in the refiner's units). Both default to the standard coupling (seedcols[t] = t, natives === nothing ⇒ derive from grid[t]). This is what the tuning grids (one fixed width parameter per spec) and the fixed-width deployment evaluations (seed at the ζ-scaled column, refit at the exactly-scaled native) are built from.

s2s[t] (the loss-width parameterization's override port): deliver the SQUARED loss width through the sanctioned s2_override port instead of a native — the column refits via refit_imc!(...; scoring = RefitJeffreys(), s2 = s2s[t]), the BITWISE-identical call solo_refit_imc! makes for override-port solo arms (asserted in test/test_engine.jl), so the tuning and the ladder's test side deliver the width identically. The spec's grid still sets the seed-sweep outlier half-width (nat′ from grid[t] — scoring only, never a width). Mutually exclusive with natives.

columns restricts which grid columns are EVALUATED (default: all). The others keep the imc matrix's NaN fill. The matrix stays full-width and every column index keeps its meaning, so boundary detection, the evaluation's seed columns and the checkpoint are untouched — this only stops computing cells that a windowed tune never reads, because it argmins inside the standardized window and the grid is far wider than that window. Measured on the PT-E 5% run of 2026-10-02: 45,567 of 386,000 cells per pair were inside the searched windows; the other 88% were computed and discarded. (A cell outside the searched window is never read by a windowed argmin.)

fixed_scale_s2s[t] (the fixed external scale port): refit at the column's native exactly as the default path (the production scoring), with the strategy deployed with_scale(lo, FixedScale(fixed_scale_s2s[t])) — the refit_imc!(…; s2) conduit — so its loss width is scale_multiple·√s2 instead of the seed partition's scale_multiple·ŝ. The partition-anchoring ablation evaluation (miscal_evaluation_refit with plugin_scale) is built from it. Combines with natives; mutually exclusive with s2s.

LocalOptimizationDoneRight.apply_lo_refits — Function
apply_lo_refits(problem_type, specs::Vector{LoRefitSpec}, pairs;
                prior = IGPrior(0.0, 0.0), operating_scale_multiple = OPERATING_SCALE_MULTIPLE,
                on_fail = nothing)
    -> Dict{String, Matrix{Float64}}

Run every refit spec over pairs and return each spec's post-LO error matrix. The run is threaded :greedy over the flat (pair × spec) product so neither a subsampled validation side nor the arms' very uneven per-spec cost leaves threads idle (see the comment in the body), with one PairCtx built per task at exactly that spec's bundle. pairs are light pool records (PoolPair): a refit never reads a residual matrix. on_fail = nothing ⇒ seed-error fallback (LO never worsens the running best); supply NaN for the ladder convention (failed refit ≠ success). Returns label => (P × T) imc matrix.

LocalOptimizationDoneRight.stream_selections — Function
stream_selections(refits_of, T, problem_type, loaders, grids, prior, backend, batch)
    -> (M::Dict{label, Vector{Matrix{T}}}, s2_by_scene, np_per)

THE scene stream of every selection+LO experiment. loaders[i]() returns scene i's (pool, residuals) (VisualGeometryEval scene_loaders(dir, scenes; residuals = true)). Per scene: stage each batch of pairs once (RSDR stage_ig_shared_from_pairs on backend), evaluate every selection grid of grids (key => (widths, scoring): the scoring's native widths and the scoring itself — RSDR grid_evaluate, or SIMFIT++'s host loop) on it, then ONE apply_lo_refits call over refits_of(idxs_of, scene_index) (idxs_of[key] = that grid's per-(pair, column) selections) on the light records. M[label] holds each refit's per-scene matrix in element type T; s2_by_scene the records' σ̂², np_per the pairs per scene. prior is the refits' scale prior.

Sample-budget engine

Walks each pair's hypothesis stream, tracks every selector's running best and refits it at the LO checkpoints.

LocalOptimizationDoneRight.SampleBudgetConfig — Type
SampleBudgetConfig

Configuration for the sample-budget selection protocol.

Fields (the schedule and the LO are REQUIRED: a sample-budget experiment

states its protocol of record, e.g. a paper's samplebudgetprotocol.toml)

  • sample_cap::Int — total minimal samples drawn per pair
  • batch_size::Int — selection (non-LO) checkpoint stride
  • lo_every::Int — LO checkpoint stride (after the first batch)
  • lo_strategy::AbstractLocalOptimization — LO method
  • budget_unit::Symbol — budget axis: :models counts essential matrices inspected (Shekhovtsov's unit); :samples counts minimal subsets.

Checkpoint schedule (both curves share one cumulative-sample x-axis)

  • Selection (running-best, no LO): every batch_size — 100, 200, …, cap.
  • LO (refit the running best): after the first batch, then the lo_every grid — {batch_size} ∪ {lo_every, 2·lo_every, …, cap} = 100, 500, 1000, ….

One MSAC/Le-Zach column of evaluate_sample_budget. It is MSAC selection at the pool-frame loss_width, its running best refit by the PoseLib truncated refiner of loss (see truncated_lo) at refinement_loss_width — the arm's tuned refinement loss width; nothing refits at the selection loss width.

LocalOptimizationDoneRight.evaluate_sample_budget — Function
evaluate_sample_budget(problem_type, methods::Vector{SampleBudgetMethodSpec}, pairs, residuals;
                       pair_ids, msac_specs::Vector{MsacSpec}, cfg::SampleBudgetConfig)
    -> SampleBudgetResults

Run the sample-budget protocol over the pool pairs pairs. The pairs are a flat vector of light pool records (PoolPair) with their residual matrices residuals (residuals[i] is pair i's; VisualGeometryEval load_pool_residuals, residual_matrix). Columns: the scoring methods, then one MSAC/Le-Zach column per MsacSpec, then the oracle (last). Parallel over pairs; per-method scoring workspaces preallocated per thread.

LocalOptimizationDoneRight.SampleBudgetResults — Type
SampleBudgetResults

Per-pair error curves for each method column, plus LO-refined error at each LO checkpoint and the LO wall-clock accounting (see summarize_lo_timing).

Fields

  • methods::Vector{Symbol} — method labels (length M)
  • sample_counts::Vector{Int} — cumulative-sample axis for batch curves (B)
  • lo_counts::Vector{Int} — cumulative-sample axis for LO checkpoints (L)
  • pair_ids::Vector{String} — per-pair identifiers (P)
  • err_batch::Array{Float32,3} — (P, M, B) running-best imc [deg]
  • best_idx_batch::Array{Int32,3} — (P, M, B) pool index of running best
  • err_lo::Array{Float32,3} — (P, M, L) LO-refined imc [deg]
  • lo_ns_total/lo_calls_total/lo_startup_ns::Vector{Int64} — per-method warm LO wall-clock [ns] / call count / cold first-call [ns] (JIT + one call)

LocalOptimizationDoneRight.summarize_lo_timing — Function
summarize_lo_timing(res::SampleBudgetResults) -> Vector{NamedTuple}

Per-method wall-clock summary: mean warm LO call [µs] (VisualGeometryEval lo_us_per_call), total warm calls, and the cold startup cost [ms]. Per-call numbers are measured in-situ under the parallel run, so they include thread contention (run single-threaded for isolated per-call cost).

A running-best selector of the sample-budget engine. It folds pool models into a running best (update!), reports that best's pose error at a checkpoint (checkpoint) and refits it through the shared refit layer (lo_error!).

OracleSelector

Oracle selector: the ground-truth-best SINGLE model by model_imc. Recomputes the imc per model (pruned by VisualGeometryCore's pool_imc, the stored lower bound on that imc) and refines that one model under LO (it carries a representative scoring and its outlier half-width).

Live end-to-end RANSAC

LocalOptimizationDoneRight.live_runs — Function
live_runs(scoring, lo, ctxs; snn_sigma, seed_of, config = RansacConfig(), warmup = true)
    -> (; err, trials, wall_s)

Run one live production ransac per E pair context ctxs[j], threaded over pairs. Each run uses the pair's pool-frame EssentialProblem(pair; sampler = GaussianSampler(pair.snn; snn_sigma)) (the problem's uniform sampler when the record carries no SNN), the selection scoring, the LO strategy lo, adaptive termination under config. Each pair's stream is StableRNG(seed_of(j)), handed to ransac explicitly, so a run is independent of the thread schedule, identical across calls that share seed_of, and fixed across Julia versions (seed_of should be a stable_seed). Per pair: err[j] the imc pose error [deg] of the final model, Inf when the run yielded no model (converged false); trials[j] the trials drawn; wall_s[j] the wall clock of the ransac call alone. warmup first runs one short solve on pair 1 (result discarded) so no bracket pays JIT.

source
LocalOptimizationDoneRight.live_row — Function
live_row(runs; T) -> NamedTuple

The summary of one live_runs result. Its fields are med the finite median error [deg], maa the mAA@T under THE eligibility rule (VisualGeometryEval eligible_maa: every pool pair is eligible, a run without a model scores 0; T defaults to its maa_threshold()), med_trials the median trials, med_wall_ms the median wall [ms], and the outcome counts (n_eligible, n_failed, n_skipped).
