Refit layer and LO strategies

Every local optimizer is refit through ONE layer. refit_imc! routes a strategy by its RefitFamily (VisualGeometryCore's trait: NativeRefit, ExternalRefit, CustomRefit), brackets the call with guarded_refit (seed fallback, non-finite fallback, timing) and returns the refined pose's error. A new optimizer needs a refit_imc! method for its family, nothing else.

The refit layer

LocalOptimizationDoneRight.refit_imc! — Function
refit_imc!(ctx::PairCtx, lo, seed_E, nat′::Float64;
           scoring = RefitMarginal(), on_fail = nothing, bundle::Bool = false,
           s2 = nothing) -> (imc::Float64, lo_ns::Int64)

Refine the metric essential seed_E with strategy lo at ITS native parameter nat′ (see consumed_native) and return the refined pose's coherent imc error [deg] plus the bracketed optimizer wall-clock.

  • scoring (NativeRefit only): a prebuilt MarginalScoring (budget selectors), or the one to build at nat′ — RefitMarginal (the default; LO matrices) or RefitJeffreys (the ladder's convention).
  • on_fail: value on optimizer bail / non-finite refit. Default = the seed's own imc (never-worsen); the ladder supplies NaN.
  • bundle: route the IRLS refit through ctx.bp (Schur reprojection bundle) instead of the Sampson pose-only ctx.ep.
  • s2: externally supplied squared scale — THE one conduit for a non-partition width, two families:
    • NativeRefit: the strategy is deployed with_scale(lo, FixedScale(s2)) (VGC scale interface) — the SANCTIONED control for role-isolated validation (solo CV, oracle-scale controls). The seed sweep still runs (selection behavior unchanged); only the LO's width is the absolute s2 instead of the seed partition's ŝ². nothing (the default, and the only production setting) keeps the strategy's own interface (partition anchor).
    • ExternalRefit: the loss width √s2 replaces nat′ (external_loss_width) — the same width either port delivers.
    • CustomRefit (PoseLibLmAdaptLossWidth): the external scale port; nothing reads the seed partition through the PRODUCTION scoring port (seed_partition_s2! — never a loss-width-window plug-in).

refit_imc!(ctx, family::RefitFamily, lo, seed, nat′, scoring, fallback, bundle, s2)
    -> (imc::Float64, lo_ns::Int64)

THE EXTENSION POINT of the refit layer: the execution path of one RefitFamily (VGC's Holy trait: NativeRefit, ExternalRefit, CustomRefit). refit_imc!(ctx, lo, seed, nat′; …) resolves the keywords — the scoring, the fallback error (on_fail, default the seed's own imc), bundle, s2 — and calls this with RefitFamily(lo). A strategy that cannot run in the native loop adds a CustomRefit method for its own type (as PoseLibLmAdaptLossWidth and the RansacLib arms (loransaclib.jl) do), wrapping its optimizer in [`guardedrefit](@ref) and scoring with [model_imc`](@ref).

LocalOptimizationDoneRight.refit_model — Function
refit_model(problem, seed, lo, scoring; workspace = nothing, s2 = nothing)
    -> Union{Nothing, model}

THE native (locally_optimize) refit of the refit layer, returning the refined MODEL — nothing when the strategy produced none. lo may be ScoreGuarded (the guard becomes score_guard). s2 deploys the SAME strategy at an absolute squared scale (with_scale(lo, FixedScale(s2)); the scoring sweep is untouched, only the LO's width moves); nothing keeps the strategy's own interface (VGC lo_scale_s2: partition-anchored in production). The refit layer's imc rows wrap exactly this in guarded_refit; a caller that needs the refined model itself (a polish warm start) calls it directly.

source
LocalOptimizationDoneRight.guarded_refit — Function
guarded_refit(opt, score, on_fail; warn_label = nothing)
    -> (err::Float64, lo_ns::Int64)

THE seed-fallback + timing bracket (replaces the four hand-rolled copies).

  • opt() -> Union{Nothing, M} — the bracketed optimizer call (data-in → result-out). Throws are caught; nothing signals bail / no consensus.
  • score(m::M) -> Float64 — GT scoring of the refined model, NOT timed. A non-finite score falls back to on_fail (a GT-free decision: the refit produced an unusable model).
  • on_fail policy is the caller's (refit_imc!'s fallback): budget/producer supply the seed's error (LO-RANSAC invariant — refinement never worsens the running best); the basin ladder supplies NaN (a failed refit did not travel).
  • lo_ns spans exactly opt().

LocalOptimizationDoneRight.truncated_refit_pose — Function
truncated_refit_pose(lo, ctx, seed_E, loss_width::Float64) -> Union{Nothing, refined pose}

The ExternalRefit E-branch optimizer body WITHOUT the guard/scoring bracket: cheirality-from-seed (fast strided vote) + PoseLib refine_relpose at the absolute pool-frame loss_width. Exposed for callers that need the REFINED MODEL (runpolishsharp's warm-started polish + support-churn diagnostic); refit_imc!(ctx, ::ExternalRefit, ...) wraps exactly this in guarded_refit.

LocalOptimizationDoneRight.RefitHalfwidth — Type
RefitHalfwidth(lo, outlier_halfwidth, scoring_of)
RefitHalfwidth(lo, outlier_halfwidth, P::Type, prior)

lo refitting under the profile-marginal scoring at ITS OWN outlier half-width instead of the selection's: the in-loop form of the refit layer's native port (refit_imc!'s nat′, refit_model). The self-scaled arms (Stu-tU IRLS, BCD) read their half-width from the scoring the loop hands them, so inside a RANSAC loop they would otherwise refit at the SELECTION half-width — not the refit half-width their sequential CV tuned at the fixed a*. scoring_of(problem) builds the refit scoring; the two-view form is MarginalScoring(P, outlier_halfwidth, prior); another loop (the ACCV project's absolute-pose race, removed from accv2026 on 2026-10-07) supplies its own scoring.

In the loop, each call re-sweeps the model under the refit scoring in the loop's own workspace and runs the loop's own Phase-2 step on that partition (RVG _lo_on_partition!): at outlier_halfwidth = the selection's it is the sweep the loop just ran, so the wrapped arm reproduces the bare arm exactly (test/testengine.jl, "live runs"). The refined model goes back to the loop, which re-scores it under the SELECTION scoring (a wrapper is not a posterior-IRLS type, so Phase 3 runs a clean sweep — the refit sweep's residuals are never reused) and keeps it only if it beats the incumbent. It is NOT the public `locallyoptimize`: that runs the seeded pipeline (score, LO, re-score, consensus, finalize) and diverged from the bare arm on 15 of 16 7-Scenes PnP queries at the selection width (the measurement that introduced this type).

LocalOptimizationDoneRight.external_loss_width — Function
external_loss_width(nat′, s2) -> Float64

The absolute loss width an external solver refines at. That is the width of an ExternalRefit solver and of the CustomRefit arms built on one: √s2 when the caller supplies a squared width through the s2 override port — the SAME quantity a native refiner's with_scale(lo, FixedScale(s2)) deploys — else the refiner's own native nat′. Both ports therefore deliver one loss width (bitwise: sqrt(w^2) == w in IEEE arithmetic); until 2026-10-01 the external arms ignored s2, so a width sent through the override never reached them.

Evaluation-only LO strategies

PoseLib's truncated refiners and the classical RansacLib LO baseline. See Baselines.

LocalOptimizationDoneRight.PoseLibLm — Type
PoseLibLm(max_iter) <: AbstractLocalOptimization

PoseLib Levenberg–Marquardt over the TRUNCATED Sampson loss (TLSShape) — the LO-RANSAC standard truncated refiner (TLS-IRLS). An evaluation-only ExternalRefit strategy: it refines at an absolute loss width through the refit layer (refit_imc!), not in the native RANSAC loop. max_iter is its LM budget (see lo_iteration_budget).

LocalOptimizationDoneRight.PoseLibLmAdaptLossWidth — Type
PoseLibLmAdaptLossWidth(; max_iter = lo_iteration_budget(), rounds, scale_multiple = OPERATING_SCALE_MULTIPLE)

Partition-anchored truncated refit (TLS-IRLS-ŝ). PoseLib LM runs over the truncated loss, its loss width re-formed between rounds LM rounds as scale_multiple·ŝ of the current model's within-width residual scale.

The initial width is anchored on the seed partition's scale (never a plug-in scale); max_iter is the total LM budget across rounds. The rounds default is [local_optimization.poselib_adapt] rounds of configs/default.toml. E-track only (PoseLib refine_relpose); a CustomRefit strategy (see the file header for the scale ingestion).

source
LocalOptimizationDoneRight.LebedaIterLO — Type
LebedaIterLO(opts::LebedaLOOptions, rng_seed::Integer)

Classical iterative-least-squares LO as an ExternalRefit strategy. It runs RansacLib's ILSQ ladder alone (lebeda_iterlo; Lebeda's LO′ mechanism) in the absolute loss-width currency (the truncation width: nat′, or √s2 through the s2_override port), seed-fallback + timing via guarded_refit. See the file header for the loss width's frame conversion. rng_seed seeds RansacLib's mt19937 on every call (its inlier-cap subsampling). Both are required: the options and the seed are protocol values of the caller.

source
LocalOptimizationDoneRight.LebedaLOPlus — Type
LebedaLOPlus(opts::LebedaLOOptions, rng_seed::Integer)

Full classical LO (RansacLib LocalOptimization run verbatim — lebeda_lo: enlarged-loss-width LSq, inner non-minimal resampling, per-sample ILSQ) as an ExternalRefit strategy. Same currency/accounting/seeding as LebedaIterLO.

source
LocalOptimizationDoneRight.ScoreGuarded — Type
ScoreGuarded(inner::AbstractLocalOptimization)

LO-RANSAC best-so-far monotonicity wrapper for IRLS-family arms. The inner LO runs unchanged, but the refined model is kept only if its SELECTION score (the same marginal that seeded it) does not drop below the seed's (RobustVisualGeometry's score_guard). It preserves score monotonicity while the optimizer descends a different objective.

Operating point and budget

The engine's defaults of record live in configs/default.toml.

LocalOptimizationDoneRight.OPERATING_SCALE_MULTIPLE — Constant
OPERATING_SCALE_MULTIPLE

The refit protocol's operating scale multiple, 2.5 by default. It is the scale multiple at which the outlier-half-width ↔ loss-width crossover is inverted when a loss-width-consuming refiner rides an outlier-half-width selector grid (consumed_native), and the operating point of PoseLibLmAdaptLossWidth's plug-in. A definition of the refit protocol, not a tuned value: configs/default.toml [refit] operating_scale_multiple.

source
LocalOptimizationDoneRight.lo_iteration_budget — Function
lo_iteration_budget() -> Int

THE equal LO model-update budget of the evaluation engine. It is configs/default.toml [local_optimization] max_iter, the default of the MSAC selector's truncated refiner (truncated_lo) and of PoseLibLmAdaptLossWidth, so arms compare at equal cost. A paper with its own protocol supplies its budget explicitly instead.

source
LocalOptimizationDoneRight.nearest_column — Function
nearest_column(grid, x) -> Int

Index of the grid column nearest x in LOG space — the deployment evaluation helper (e.g. the column of the ζ-scaled tuned native). Evaluation only; tuning is always a windowed free argmin, never nearest-column selection.
