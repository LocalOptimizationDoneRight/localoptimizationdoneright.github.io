Overview

LocalOptimizationDoneRight is the local-optimization (LO) evaluation engine of the ACCV 2026 paper Robust Local Optimization Done Right. It evaluates how a RANSAC local optimizer refines the hypothesis a scorer selected, on stored hypothesis pools, so that the effects of the robust loss, the inlier scale and the optimization strategy can be isolated from sampling. The repository has two halves:

the package (src/engines/)pair geometry, the one refit layer, the PoseLib and RansacLib LO arms, post-LO error matrices, the sample-budget engine, live RANSAC runs, arms and rosters with their gate-enforced readers, the selection stream
the research project (accv2026/)the paper's arm table, configs, drivers, renderers and manuscript — see Reproducing the paper

The engine sits on the rest of the stack: VisualGeometryCore (models, pool records, the RefitFamily and WidthAxis traits), RobustVisualGeometry (problems, ransac, locally_optimize), RansacScoringDoneRight (the scorers and the selection sweeps) and VisualGeometryEval (pool IO, statistics, the tuning artifacts).

Scoring versus refinement

RANSAC asks two different questions of a robust objective. Scoring ranks minimal-sample hypotheses and must be sharp: a single wrong inlier set loses the pair. Refinement moves the selected hypothesis toward the solution and needs a soft objective: gradient from correspondences that the seed currently rejects. The engine keeps the two roles separate throughout:

  • a selection sweep (RansacScoringDoneRight grid_evaluate) scores every pool model of a pair at every width on a grid and records, per (pair, column), the index of the model it selected;
  • a refit refines that selected model with one local optimizer at one width and records the refined pose's error (model_imc, degrees).

Because the selection is computed once and shared, every optimizer is compared on exactly the same seeds.

Pools and pair geometry

A pool pair is VisualGeometryCore's light PoolPair record: correspondences, minimal-sample models and ground truth stored in the NormalizedImageFrame (image centre, half diagonal), with the maps that put them there. build_pair_ctx builds the per-pair PairCtx once — the pool-frame problem, the calibration, the ground truth and a workspace cache — and every selector and refit of that pair reuses it. Essential-matrix problems work on unit bearings back-projected by the pool-frame camera; refit_seed upgrades a stored pool-frame fundamental to the metric essential seed.

The refit layer

Every optimizer is refit through ONE call, refit_imc!(ctx, lo, seed, nat′). It routes the strategy lo by its RefitFamily trait:

familystrategieshow the width arrives
NativeRefit (default)every IRLS, HQ, GNC and BCD strategy of RobustVisualGeometry, through locally_optimizepartition-anchored: the scale is read from the seed's inlier partition
ExternalRefitPoseLibLm, PoseLibLZ, LebedaIterLO, LebedaLOPlusan absolute loss width (external_loss_width)
CustomRefitPoseLibLmAdaptLossWidthpartition-anchored start, re-estimated between rounds

guarded_refit brackets every call: the seed is kept if the optimizer fails or returns a non-finite model, and the optimizer's wall-clock is measured inside the bracket. A new optimizer needs no per-type code if it implements locally_optimize; an external solver adds one refit_imc! method for its family.

Widths: axes, parameterizations and ports

A width is a value on a VisualGeometryCore WidthAxis:

  • OutlierHalfwidth() — the Student-t marginal scorer's uniform outlier half-width (the axis of profile-marginal selection);
  • LossWidth() — a threshold score's truncation width, in absolute residual units;
  • ScaleMultiple() — a dimensionless multiple k of the scale ŝ estimated from the seed's inlier partition (partition anchoring: the loss width is k·ŝ).

The first two are native axes (NativeAxis) on which a selection grid lives; a scale multiple is a parameterization only. consumed_axis and consumed_native convert a selection-grid value to the axis a refiner consumes, and loss_width_port says how a loss width reaches it — through the s2 override (OverridePort) for a native refiner, natively (NativePort) for an external one.

Arms

An arm is one evaluated pipeline.

  • ComposedSpec(base, sel, selection, kind, ctor; source) — a composed score + LO pipeline: sel keys the selection sweep it seeds from, selection is that sweep's native axis, kind the arm's width parameterization, and ctor(value) builds the LO strategy at a width value.
  • SoloSpec(base, role, axis, ctor) — one role (:selection or :refinement) validated in isolation at one absolute width; the basin experiment refines perturbed ground-truth seeds this way (solo_refit_imc!).

Width sources

Where a composed arm's refit width value comes from is its WidthSource:

  • TunedWidth — the arm's own width, tuned by the refiner stage of the cross-validation at its selector's tuned selection width a*;
  • SelectionWidth — the refit width is a*, never tuned. Only an arm whose width axis is its selection axis can take it: an outlier-half-width refit of a Student-t marginal selection, the strictly objective-matched arm.

operating_width reads the width an arm refits at, and width_delivery how it is delivered to the refit.

Rosters and the gate-enforced readers

A paper states its arms in one Roster(composed, solo, basin) value — three builders from a problem (:E, :F, :H) to its arms — and hands it to every reader of a tuned operating point. There is no global registry.

The tuning writes, per arm, the axes on which its cross-validation window clipped the optimum (boundary_hits). The readers — deployed_budget_settings, deployed_arm_settings, deployed_basin_settings — rebuild the arms through the roster and refuse any arm with a clipped operating point (the interior-argmin invariant). audit_operating_points runs the right reader on a sidecar and is mandatory before a figure or table consumes it.

Evaluation engines

  • Post-LO error matrices. LoRefitSpec describes one refit of a selection sweep; apply_lo_refits turns a vector of them into (pairs × grid) error matrices, building each pair's context once. stream_selections feeds it scene by scene from a selection grid. miscal_evaluation_refit builds the refit of the scale-miscalibration study, where a factor ζ corrupts the supplied scale.
  • Sample budget. evaluate_sample_budget walks each pair's hypothesis stream, tracks every selector's running best and refits it at fixed checkpoints (SampleBudgetConfig), so accuracy is measured against the number of minimal models inspected.
  • Live RANSAC. live_runs runs the production ransac loop on the pool pairs (resampling, adaptive termination, in-loop LO); live_row summarizes a run.

Defaults of record

Every engine default that changes a selection or a refit and is not a tuning parameter lives in configs/default.toml, read through one function, _config_default(table, key), which throws on a missing table or key — there is no second set of Julia literals. The file is parsed at precompile time, so an edit forces a recompile.

A paper with its own protocol states its values explicitly; the ACCV 2026 protocol of record is accv2026/configs/protocol.toml.

Frames

Frame in, frame out: public functions return results in the frame their inputs came in. The one declared exception is the benchmark pool, stored in NormalizedImageFrame; every API where pool data enters or leaves names that frame. Calibrated geometry is on unit bearings — except for the vendored RansacLib essential-matrix arm, a declared third-party pinhole exception (see Baselines).
